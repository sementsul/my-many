# MyMany — юзер-кейсы (живой список)

## UC-01. Дашборд «Монитор крипторынка» на главной ✅
**Предусловие:** любой посетитель открывает my-many.ru.
**Шаги:** 1) открыть `/`; 2) увидеть метрики рынка; 3) при желании обменять — клик по CTA «Перейти на RateScout».
**Ожидаемо:** SSR-страница (данные вшиты в HTML для индексации): капитализация рынка, изменение 24ч, доминация BTC/ETH,
объём торгов, индекс страха и жадности, топ-5 роста и падения за 24ч, топ-20 монет по капитализации; внизу CTA на ratescout
(utm_source=mymany). Обновлено-метка + «данные CoinGecko».
**РАДИУС:** `build.py` (единственный генератор) → `dist/index.html` + sitemap/robots/CNAME. СОСЕДИ/роли: ratescout НЕ затронут;
🔴 контент намеренно НЕ дублирует ratescout (другой интент — обзор рынка, не обмен) во избежание каннибализации.
**Проверка:** `python3 build.py` EXIT 0 на живых данных (капитализация ≈ $2.6 трлн); 20 монет + 10 лидеров в HTML;
CTA с utm присутствует. **Статус:** ✅ v1 собран локально; ⏳ не задеплоен (ждёт репо + DNS Cloudflare→Pages).

## UC-02. Автообновление данных (крон) + деплой на Pages ✅ (код)
**Предусловие:** репо `sementsul/my-many` создан, в Settings→Pages источник = «GitHub Actions».
**Шаги:** `.github/workflows/deploy.yml` по расписанию (ежечасно, cron `17 * * * *`) + при пуше в main + вручную →
`build.py` собирает dist → `upload-pages-artifact` + `deploy-pages` публикуют в GitHub Pages.
**Ожидаемо:** метрики на сайте свежие без ручных действий; при недоступности API — фолбэк на кэш `data/*.json`.
**РАДИУС:** `.github/workflows/deploy.yml` (permissions pages:write, id-token:write). СОСЕДИ: не влияет на ratescout.
**Статус:** ✅ воркфлоу добавлен и запушен; ⏳ первый успешный деплой — после включения Pages-источника «GitHub Actions»
владельцем + настройки DNS (Cloudflare CNAME @→sementsul.github.io, SSL Full).

## UC-03. Индексация в поиске ⏳
**Предусловие:** сайт задеплоен на домене.
**Шаги:** подключить Яндекс.Вебмастер + Google Search Console, отправить `sitemap.xml`.
**Ожидаемо:** страница попадает в индекс; ранжирование — постепенно (домен молодой, без авторитета).
**Статус:** ⏳ после деплоя.

## UC-04. Аналитика (Яндекс.Метрика + Google Analytics) ✅
**Предусловие:** нужно считать трафик my-many теми же счётчиками, что ratescout.
**Шаги:** `build.py` вставляет в `<head>` Метрику `111586112` + GA `G-PPN27D6JXS` (константа ANALYTICS).
**Ожидаемо:** визиты попадают в Метрику/GA. 🔴 my-many.ru нужно ДОБАВИТЬ в список доменов счётчика Метрики
(иначе визиты не зачтутся); данные my-many смешаются с ratescout в общем счётчике (принятый компромисс, можно завести отдельный).
**РАДИУС:** `build.py` (только `<head>`). СОСЕДи: ratescout не тронут (там свои же счётчики).
**Проверка:** в `dist/index.html` по 1 вхождению tag.js?id=111586112 и gtag?id=G-PPN27D6JXS. **Статус:** ✅ код.

## UC-05. Keep-alive крона (PAT) ✅ (код)
**Предусловие:** GitHub отключает scheduled-воркфлоу после 60 дней без КОММИТОВ; deploy.yml коммитов не делает.
**Шаги:** `keepalive.yml` (еженедельно, пн) чекаутит с `secrets.GH_PAT` → пишет `.keepalive` (метка времени) →
коммит+пуш ПОД PAT (коммит через GITHUB_TOKEN таймер не сбрасывает).
**Ожидаемо:** репо получает коммит раз в неделю → 60-дневный таймер не истекает → deploy.yml по крону не засыпает.
**РАДИУС:** `.github/workflows/keepalive.yml`. 🔴 Требует секрет `GH_PAT` в ЭТОМ репо (secrets межрепозиторно не шарятся).
**Статус:** ✅ воркфлоу добавлен; ⏳ заработает после добавления секрета `GH_PAT` владельцем.

## 🧭 РЕШЕНИЕ по «лендингу для ratescout» (анти-фильтр)
my-many НЕ делаем голым переходником на ratescout (=дорвей → фильтр Google/Яндекса, риск задеть и ratescout по связке,
особенно при общем счётчике Метрики). Оставляем самоценный монитор рынка + усиленный промо-блок/CTA на ratescout.
Разница: страница имеет собственную пользу, а не только «слив» трафика.
