# MyMany — юзер-кейсы (живой список)

**Проект переделан 2026-09-06:** из «монитора крипторынка» (CoinGecko) → **арбитражная база цепочек обмена**
(данные BestChange через ratescout). Старые UC-01…06 (рыночный дашборд) неактуальны — заменены ниже.

## UC-A1. Монитор арбитражных цепочек на главной ✅
**Предусловие:** посетитель открывает my-many.ru.
**Шаги:** 1) открыть `/`; 2) видит статы базы (сколько цепочек/валют, лучшая доходность) + таблицу цепочек;
3) переключает режим (2/3/4 звена), сортировку (доходность/риск), фильтр по стартовой валюте; 4) «показать ещё»;
5) клик по цепочке → страница цепочки.
**Ожидаемо:** монитор в стиле ratescout (его styles.css): путь цепочки (BTC→…→BTC), доходность+мини-бар, риск (бейдж+бар),
мин. обменников. Топ-800 встроены в HTML (быстро, индексируется). Дата обновления + «данные BestChange».
**РАДИУС:** `build.py` (`render_home`, `HOME_JS`). Данные из `compute_shards`. СОСЕДИ: ratescout не затронут (только читаем его rates.json).
**Проверка:** build EXIT 0 (18 444 цепочки/166 валют); node --check HOME_JS OK; DOM-стаб → 60 строк, 120 мини-баров, 60 ссылок на /c/. **Статус:** ✅ (визуальная приёмка на проде — за владельцем).

## UC-A2. Страница цепочки + калькулятор ✅
**Предусловие:** клик по цепочке в мониторе или на странице валюты (`/c/?s=<slug>&i=<index>`).
**Шаги:** 1) страница грузит шард `data/chains/<slug>.json`, берёт цепочку по индексу; 2) показывает пошаговую конверсию
(на каждом шаге: отдаёте / курс / получаете, ссылка шага → BestChange для реального обмена); 3) пользователь вводит сумму в
стартовой валюте → калькулятор считает, сколько получит по текущим курсам и итоговую прибыль (сумма и %).
**Ожидаемо:** итог калькулятора = заявленной доходности (проверено: 0 расхождений на 120 цепочках; курсы — полный float).
Перелинковка: стартовая валюта → ratescout `/valuta/<slug>/`, CTA «обменять на RateScout». Под дисклеймером — центрированная кнопка «💰 Арбитраж — все цепочки» → на главный монитор `/` (`.mm-cta`).
**РАДИУС:** `build.py` (`render_detail_page`, `DETAIL_JS`) + шарды. **Проверка:** build EXIT 0; node --check DETAIL_JS OK;
математика калькулятора сверена с хранимым профитом. **Статус:** ✅ (клиентская загрузка на проде — за владельцем).

## UC-A3. Страницы входа по стартовой валюте (SEO) ✅
**Предусловие:** «у меня есть BTC» → `/valuta/bitcoin/` (или любая валюта с цепочками).
**Шаги:** открыть страницу → SSR-таблица всех цепочек, начинающихся с этой валюты (путь/доходность/риск/обменников/тип),
клик → страница цепочки; перелинковка на ratescout `/valuta/<slug>/`.
**Ожидаемо:** 166 страниц (по валютам с ≥1 цепочкой), в sitemap (hourly, 0.7). Уникальный интент «арбитраж с X».
**РАДИУС:** `build.py` (`render_currency`, sitemap). **Проверка:** build EXIT 0, 166 стр.; bitcoin/index.html ссылается на /c/?s=bitcoin. **Статус:** ✅.

## UC-A4. Данные из ratescout + автодеплой 15 мин + keepalive
**Предусловие:** ratescout публикует `https://ratescout.ru/rates.json` (добавлен экспорт в его build.py).
**Шаги:** `deploy.yml` cron `*/15` (+сдвиг) + push + dispatch → `build.py` тянет rates.json (ratescout.ru), history/currencies
(raw-GitHub), фолбэк на кэш → dist → Pages. `keepalive.yml` — недельный PAT-коммит (чтобы крон не уснул за 60 дней).
**Ожидаемо:** база обновляется автоматически. 🧭 «15 мин» = частота сборки; данные свежеют с обновлением rates.json (~ежечасно).
**РАДИУС:** `mymany/.github/workflows/deploy.yml` (cron) + `ratescout/build.py` (экспорт rates.json). **Статус:** ✅ код; ⏳ первый деплой после публикации rates.json на ratescout.
**Долг:** ⏳ автопостинг по API (доп. к keepalive) — ждём ключ/цель от владельца.
